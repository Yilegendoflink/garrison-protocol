# PRTS 原作数据库

采集快照：`2026-09-12-prts`。这是原作参考资料数据库，尚不是可直接加载进战斗引擎的完整可执行内容包。

## 已完成的全目录采集

| 类型 | 数量 | 口径 |
| --- | ---: | --- |
| 干员条目 | 460 | PRTS干员分类，包含29个专属条目；不等于国服常规可获得干员数 |
| 敌人条目 | 1,804 | PRTS敌人分类，包含非常规单位 |
| 召唤物条目 | 71 | PRTS召唤物分类 |
| 技能记录 | 1,005 | 包含页面列出的技能等级／专精字段 |
| 专属模组 | 499 | 排除386个基础证章；模组各级字段保存在记录中 |
| 敌人等级记录 | 2,082 | 同一敌人的不同等级分开保存，缺省字段追踪继承 |
| 范围定义 | 77 | PRTS Range微件，64个完成常规展示网格解析，13个待核对 |

四个分类合并去重后共2,335个页面。每页记录页面ID、修订ID、修订时间、采集时间、原文哈希和固定版本链接。

数据来源：[干员目录](https://prts.wiki/w/干员一览)、[敌人分类](https://prts.wiki/w/分类:敌人)、[专属干员目录](https://prts.wiki/w/干员一览/专属干员)、[召唤物分类](https://prts.wiki/w/分类:召唤物)，通过PRTS的MediaWiki API分页读取。

## 文件

- `latest.json`：本地当前快照指针。
- `snapshots/2026-09-12-prts/database.sqlite`：SQLite查询库。
- 同目录 `operators.json`、`enemies.json`、`summons.json`、`ranges.json`：可移植JSON主数据。
- `inventory.json`：分类目录清单，用来发现漏采和重复。
- `source/`：各页面抽取的战斗相关模板；保留原字段，不执行Wiki模板。
- `range-sources.json`：范围微件的原始定义，仅作为数据读取。
- `coverage.json`：完成度和未解决字段。
- `manifest.json`：采集范围、计数、源文件和主数据SHA256。
- `database.sqlite.metadata.json`：SQLite文件哈希与所用manifest哈希。

JSON是主数据，SQLite为可重建导出。采集覆盖一次请求时间窗口，页面各有独立修订号；这不是Wiki全站在某一瞬间的事务快照，也不是特定客户端版本的完整数据镜像。

## 常用命令

在项目根目录执行，无需npm install。JSON工具使用项目现有Node.js环境；SQLite导出使用内置 `node:sqlite`，已在Node.js 24.16.0验证，Node.js 22需22.13或更新版本。

```powershell
npm run data:stats
npm run data:check
npm run data:query -- search operator 能天使
npm run data:query -- show enemy 源石虫
npm run data:query -- show range 3-3
npm run data:sqlite
```

采集一个新的当前快照：

```powershell
npm run data:sync
```

中断后用相同快照名续传；重新规范化已采集字段时可完全离线：

```powershell
node scripts/sync-prts.mjs --snapshot=2026-09-12-prts --offline
```

同名快照只复用已有目录，不会自动更新目录成员。获取最新全目录应创建新快照。显式补采已有分类页可使用 `--refresh-category=召唤物`；会更新该工作快照对应页面的修订记录，故正式发布包应另外固定、保留快照及哈希。

离线重建JSON后需重新执行 `npm run data:sqlite`。SQLite元数据固定当时主数据manifest，避免把旧SQL库误当成新导出。

采集器限制串行请求间隔，处理限流和服务繁忙，分批缓存，发生错误时不会把未完成结果设为latest。源数据不包含账号凭据，不采集立绘、音频或剧情档案。

## 数据语义

### 干员

主键 `prts:operator:<pageId>`；原作内部ID另存 `gameId`。稀有度从PRTS的0起始值转换为1–6星，保留原字段以便核查。

保存职业、分支、部署位置、各精英阶段属性锚点、费用／阻挡／再部署／攻击间隔原值、信赖、潜能、技能、天赋、模组和范围ID。基础属性不把天赋、模组或卫戍协议加成提前混进去。

技能保存原回复类型、原触发类型、各等级初始SP／消耗／持续，以及原规则文本。自动触发不等于“下次攻击”，后者必须进一步核对其动作语义。技能描述中的数字不能仅靠正则匹配直接变成效果程序。

没有技能模板的22个单位标记 `none-declared`，不直接判定为漏采或给它们虚构技能。

属性起始值推导参考[PRTS属性计算器固定修订306583](https://prts.wiki/index.php?oldid=306583)：生命／攻击／防御按相邻阶段锚点插值，法抗取当前精英阶段常量。推导锚点另存 `derivedAnchors` 和规则来源，不冒充页面直接给定值。当前阶段锚点已能补齐，但仍需在历史客户端数据上核对成长、取整及特殊例外。

### 敌人

主键 `prts:enemy:<pageId>`；`codexId`是图鉴编号，`sortId`是PRTS排序号，二者均不能冒充客户端 `enemyId`。当前全部敌人 `gameId` 保持null，等待可靠映射。

每个等级记录原始覆盖字段、继承后的字段、继承来源和规范化数值。只允许继承已存在的前一个数字等级；显式空字符串不会变成0，也不会越过缺失等级继承。Wiki模板的展示默认值不自动当成已确认游戏数值。

通常属性与关卡／难度／模式覆盖分开保存。等级、阶段形态与重生形态也不是同一个概念，不能把所有变体硬塞进等级数字。

### 范围与召唤物

展示范围区分中心格和轮廓格，保留PRTS范围ID。中心格是否具有攻击触发、目标碰撞半径与技能范围变化另行核实，不能由SVG展示推断全部攻击规则。

召唤物保留持有者名称、属性模板、技能和天赋来源。所有权、部署占用、离场联动和自动再部署还需要转成可执行生命周期规则。

## 已知缺口

- `同构碎片`页面没有等级属性模板：已归档条目，未虚构HP等数值。
- 敌人等级规范字段中存在6,920个未给定／不可直接数值化的值，其中包含无攻击半径等不适用字段；这不是6,920个确定的数据错误。需要逐字段分类为不适用、模板默认、资料缺失或待求值。
- 1,804个敌人内部ID尚未建立映射。
- 13个特殊范围展示定义尚未自动转换，原始定义完整保留。
- 天赋、模组、技能规则文字已归档，但尚未全部成为可执行效果；敌人正文中的特殊AI仍需逐项结构化。
- 本快照为2026-09-12的Wiki状态，包含卫戍协议下半期之后的新增／修改内容。历史还原必须选用相应基础数据版本，再叠加活动改动。

因此目前完成的是全目录参考库与主要战斗字段采集。不得把“2,335页全部取得”表述为“所有技能、AI和历史版本均已还原”。完整性报告必须同时展示目录覆盖率、字段完整性和执行支持率。

## 与卫戍协议的关系

后续按三层组合：

1. 原作基础数据库：通用干员、技能、模组、敌人、范围和召唤物。
2. 卫戍协议期次数据：对应基础版本、可用名单、固定养成、初始／精锐模板、特质、盟约、装备、策略及敌人覆盖。
3. 关卡实例：地图、路线、波次、难度、随机条件和局内状态。

自定义包引用这套基础数据并声明覆盖项。禁止直接改基础记录来“适配卫戍协议”，也不能让当前Wiki新增角色自动进入历史活动池。

## 来源与使用

数据库记录保留PRTS修订链接与来源；中文规则、名称等用于机制研究，图片与音频未下载。来源声明与适用许可参见[PRTS关于页面](https://prts.wiki/w/PRTS:关于)及对应原页面；原作素材和游戏文本权利归原权利人。后续分发时保留来源、修改说明和适用许可信息。
