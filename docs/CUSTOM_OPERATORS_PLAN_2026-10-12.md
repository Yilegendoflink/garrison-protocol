# 自选干员系统实施方案

日期：2026-10-12。状态：方案已进入实装，可运行首版接入；现状、测试证据与原作待核定项见 [实装记录](CUSTOM_OPERATORS_IMPLEMENTATION_2026-10-12.md)。以下阶段表仍是完整验收标准，不表示全部已通过。

目标是在开局前配置最多两名本期预设阵容之外的干员，每名独立选择五阶或六阶，加入本局干员获取池。首批为维什戴尔、赤刃明霄陈、阿斯卡纶、望、克莱门莎。系统接入、逐名战斗机制、整局验收分别推进；只完成配置界面或数据建档不能宣布五名干员可玩验收完成。

逐名施工以 [五名自选干员 PRTS 数据与机制核对](CUSTOM_OPERATORS_PRTS_AUDIT_2026-10-12.md) 为详细依据。该核对已保存固定版本页面与全部技能等级，对模组余震、特殊伤害来源、放逐组合及来源歧义有补充；本页保持系统接入与阶段安排。

十五个技能的开技、攻击、持续对象、资源提示、结束与低特效要求见 [技能视觉效果规格](CUSTOM_OPERATORS_VISUAL_SPEC_2026-10-12.md)。程序化表现与 Spine／原作美术验收分别记录，不能只给每人一个开技光圈就视为技能表现完整。

## 已确认规则与实施默认值

### 已确认规则

- 两个名额是全局总数，不是五阶两个加六阶两个。可以配置两个五阶、两个六阶或各一名。
- 加入干员池后仍通过商店和适用的奖励渠道获取，不在开局直接赠送干员。
- 自选干员没有自带卫戍特质，初始和精锐档案的 `garrisonIds` 均为 `[]`。干员本身的职业特性、天赋、技能与模组保留。
- 维什戴尔、阿斯卡纶的“无”表示没有核心阵营；用户已确认按 PRTS 归入协防干员。
- 赤刃明霄陈、望属于炎；克莱门莎属于阿戈尔。不得从通用势力字段再自动附加叙拉古、独行、迅捷等盟约。
- 用户已追加授权实装开发；发布仍未执行。

[PRTS 自选规则](https://prts.wiki/w/卫戍协议：盟约_下半/PRTS盟约记录)用于参考获取方式和身份口径；名额数量与首批名单采用本次用户要求。

### 建议采用的默认值

以下是实施建议，不应描述为用户已逐项确认的规则。

- 允许空着一个或两个名额，默认都为空，旧玩家的默认池保持现状。
- 同一 `charId` 只占一个名额，不同时选作五阶和六阶；异格身份按不同 `charId` 处理。
- 本地保存配置，生成战前简报时复制进开局草案；当前对局和恢复存档不读取后来的大厅改动。
- 阶级只允许整数 5、6；未知干员、第三个名额、重复身份不能进入开局与存档。
- 技能选择复用战前准备，默认沿用 DIY 槽的第一技能；不增加潜能、信赖和模组选择器。
- 首批已有模组的四人建议固定使用 X 模组 `uniequip_002_*`；阿斯卡纶的 Y 模组已在详细核对中登记，是否开放另列范围。克莱门莎本次固定 PRTS 页面没有模组，扩展原表仍须交叉校验，不生成虚构模组。
- 继承当前客户端全干员的养成属性加成通道，不因“没有卫戍特质”去除装备、盟约、策略或其它干员发放的效果。无自带特质不等于免疫获得额外特质。
- 普通模拟、325、海猫和 S.E.E.S. 策略均可采用自选配置；每周挑战是否允许使用由挑战快照明确控制，建议缺省允许、锁定阵容的挑战可关闭。训练与沙盒另做入口适配，不擅自改变训练课程。

## 数据与运行链路

### 实装前的代码边界（历史基线）

1. 历史表有四个空 DIY 槽，但 `charId:null`，构建和商店会跳过，尚无自选入口。
2. DIY 槽的 `garrisonIds:null`；直接填 `charId` 后调用 `resolveChess` 会在 `.map()` 报错。所有扩展档案须先规范成 `[]`，获得事件中的 `.some()` 也依赖这个数组口径。
3. 前四人均在 `data/normalized/allianceLower.json` 中，技能、范围与高级模组数据可用；五人均未有对应可玩档案，未检索到专属处理器。`bombarder` 仍标记余震时序待校准，`traper` 仍标记陷阱实体与部署条件待补。
4. 克莱门莎未在本地历史包和 `current` 包中；PRTS 记录其 2026-10-09 上线。必须补固定提交的扩展数据，不能替换整季基础包为最新版本。
5. 五人和新增附属对象的头像需补到资产 manifest。`build-token-data.mjs` 会重新覆盖 `runtime.tokens`，新增依赖不能只注入 `build-native` 后就认为会保留。
6. `bondRoster` 按数据对象做 WeakMap 缓存且跳过隐藏记录；只让商店放行隐藏棋子会使禁用预览、同盟约奖励和战前准备漏人。
7. `NativeSession.restore` 先验证单位和商店棋子是否存在于 `data.profiles`，读取自选配置和重建本局可见池必须安排在验证之前。

### 推荐数据结构

新增登记表 `data/modes/alliance-lower/custom-operators.json`，只登记实体、身份、模组、别名、来源和可用状态，不抄写整套数值。

```json
{
  "version": 1,
  "maxSlots": 2,
  "allowedTiers": [5, 6],
  "operators": [
    {
      "charId": "char_1035_wisdel",
      "name": "维什戴尔",
      "bondIds": ["emptyShip"],
      "defaultUniEquipId": "uniequip_002_wisdel"
    }
  ]
}
```

本地配置及对局快照只存选择，不存玩家可伪造的属性、技能黑板或盟约：

```json
{
  "version": 1,
  "slots": [
    {"charId": "char_1035_wisdel", "tier": 5},
    {"charId": "char_1050_chen3", "tier": 6}
  ]
}
```

### 推荐接入方式

使用原有 DIY 状态作为模板，构建五人 × 两阶 × 初始／精锐的 **20 个稳定档案 ID**，例如 `chess_custom_wisdel_5_a/b`。它们在基础数据中隐藏，不给默认商店库存；同一 ID 永远对应同一人、同一阶级。不要把某个持久化的 `diy1` 棋子 ID 随玩家改选绑定成另一名干员。

每次生成简报、开局、恢复存档时，按已校验的选择创建轻量数据视图：仅复制商店记录表及需要公开的选中记录，将本局选中的两个初始档案解除隐藏；实体、地图、技能和已建档的 profiles 仍共享只读基础数据。局内 `session.data`、战斗、禁用名册和奖励都使用该视图，原始 `NATIVE_DATA` 不变。这样可以复用现有可见性过滤，不再为各渠道维护一套自选白名单。

完整流程为：大厅配置 → 已校验选择 → 简报草案快照与本局名册 → `NativeSession` → 库存／获取／三合一 → `NativeBattle` → 对局存档与战报。

| 位置 | 必要工作 |
| --- | --- |
| `scripts/build-native.mjs` 与新增构建辅助函数 | 从 DIY 模板建稳定档案，补 `chessNormalIdLookupDict`，生成三个技能选择；校验技能、范围、模组、token 引用 |
| `scripts/build-token-data.mjs` | 合并已登记扩展召唤物；避免覆盖掉扩展数据或改变历史 token |
| 新增 `dist/native-custom-operators.js` | 配置校验、读写、本局数据视图；保持纯数据依赖，不 import session／battle／play |
| `dist/native-session.js` | 构造函数在首次库存和抽卡前应用本局视图；快照保存选择；恢复时先验证选择再验证棋子 |
| `dist/protocol.js` 与 `native-economy.js` | 复用价格、库存和合成；修复实际遇到的空数组兼容；核对固定发放和晋升奖励门禁 |
| `dist/native-bond-ban.js` | 让已选名册参与现有“所属盟约全部被禁”规则，初始／精锐归一；新视图避免复用旧缓存 |
| `dist/native-prep.js` 与 `native-play.js` | 配置、阶级预览、技能选择、简报、沙盒；局内名单读取本局视图 |
| `dist/native-operator-effects.js`、`native-effects.js`、`native-battle.js` | 逐名事件处理；需要复杂状态机时拆独立专属模块 |
| `dist/native-branches.js` 与 `native-sp.js` | 按技能／伤害段区分对空，支持非普攻消耗的弹药与专属阻回 |
| `scripts/build-browser.mjs` | 登记新增运行模块，完成离线 bundle 构建 |
| 头像同步与 Android manifest | 资产有可复核来源，完整构建后进入预缓存清单 |

未选中的三人、选中人物的另一阶不能通过刷新、晋升奖励、具名池、固定发放或伪造存档泄漏。沙盒可查看首批全部档案，但该权限不得影响普通对局。S.E.E.S. 解锁与策略池门禁继续独立执行。

## 界面和交互

建议在大厅“战前准备”增加“自选干员”页签，不再扩充协议自定义的两页编制台。页面始终显示两个位置，每个位置可选人物、切换五阶／六阶、查看初始和精锐属性、清空；列表仅有首批五人，重复选择禁用。切阶保留人物和已选技能。

卡片明确显示“自选”“五阶／六阶”“炎／阿戈尔／协防干员”和“无自带卫戍特质”。切换阶级立即更新两态属性及模组信息，避免把基础属性表写成最终战斗属性。已有“全干员”页按当前配置加入被选中的两名，技能选择仍按 `charId` 保存。

简报显示已固定的两名和阶级。若所属盟约被禁，卡片显示本局不可获取及原因；不自动换人、不偷偷重抽禁用。维什戴尔与阿斯卡纶默认受协防干员的禁用配置管理，炎与阿戈尔各自受对应禁用管理。取消简报再重新开局，才采用新的配置。

新增战斗投放能力用于望的棋子，包含可用数量、合法格、预览连线、确认和取消；备战布局与战斗消耗按对象类型分开。维什戴尔的魂灵之影由天赋和技能自动选位，不变成可任意拖放的战术家援军卡。手机按钮不少于 44px，桌面与手机均验证档案、装备拖放和棋子投放不会互相遮挡。

## 逐名战斗机制与验收

四名已有数据的数值由历史 normalized 包读取。PRTS 备注用于补充原表黑板没有表达的索敌、伤害分类、退场和交互语义；遇到版本差异记录差异，不把当前新增模组自动扩成首批默认范围。所有下面的验收都是待开发检查项。

### 维什戴尔

实体 `char_1035_wisdel`，分支 `bombarder`。需要明确区分主攻击、余震和残影爆炸。数值见历史包；目标与爆炸规则依据 [PRTS 维什戴尔](https://prts.wiki/index.php?oldid=435184)，附属对象依据 [PRTS 魂灵之影](https://prts.wiki/index.php?oldid=386827)。

| 能力 | 实施内容 | 定向验收 |
| --- | --- | --- |
| 投掷手普攻 | 主攻击与真实延迟余震独立结算，维护 `attackId` 和来源 | 余震期间目标移动／死亡，范围与延迟仍按核定规则；不把当前通用余震近似当完成 |
| 好礼 | 主目标倍率、附着残影、余震独立概率引爆、爆炸与眩晕 | 残影不叠加；爆炸不递归触发自己；撤退清残影；爆炸可对空 |
| 死魂灵的余息 | 部署后自动召唤魂灵之影与迷彩联动 | 合法位置不足、被击败、主人撤退均可结束；不为所有友方永久发迷彩 |
| S1 定点清算 | 下一次攻击增加两次余震、调整余震倍率与溅射、附加眩晕 | 无模组共三次余震，X 模组在基础两次上追加两次；总段数与真实时序分别验证，攻回不因余震变成额外普攻 |
| S2 饱和复仇 | 普通阶段最多三个目标；过载阶段四次独立随机选目标；主动停止 | 前后两阶段正确切换；不在四连发之外再额外攻击三人；随机序列恢复一致 |
| S3 爆裂黎明 | 自动补魂灵之影、锁定主目标、六发弹药、强化范围与必触发残影 | 技能 4 级新增一影，7 级新增两影，总数上限三；一轮普攻扣一发；结束保留影 |
| 魂灵之影 | `token_10035_wisdel_wward` 的属性、技能 SP、选位和主人关系 | 只用技能、不普通攻击，优先无残影地面目标；S3 新影的初始 SP 分别处理 |
| X 模组 | 属性、余震特性调整与第一天赋强化 | 初始无模组；五阶模组 1 级与六阶模组 3 级各有损伤结果证据 |

魂灵之影不占干员部署位，但其落格占用、禁疗、数量和退场必须按 token 单独登记；不要套用海嗣、医疗无人机或战术家卡的整套生命周期。S3 的普攻／溅射可对空与影的技能不可对空要同时成立。迷彩需要保留该角色的阻挡例外，不能直接采用通用“阻挡后显形”作为全部规则。

### 望

实体 `char_2027_wang`，分支 `traper`。这是首批主要交互与实体工程：手动部署的棋子是 token，天赋跟子是附属弹道，两者可参加连线，但占位、伤害来源与放置条件不同。数值见历史包，区别依据 [PRTS 望](https://prts.wiki/index.php?oldid=435179)。

| 能力 | 实施内容 | 定向验收 |
| --- | --- | --- |
| 铸子 | 棋子库存、部署上限、连线激活和额外跟子选位 | 同格规则正确；跟子按有敌人、地形及上下左右优先序生成；没有空间不报错 |
| 料敌机先 | 连续直线计数、叠加上限、伤害提升和本次伤害法抗穿透 | 横／纵／十字／断线各留场景；伤害后不污染来源的永久穿透属性 |
| S1 取势 | 被动触发停顿与持续法术伤害，主动补两枚棋子 | 满库存不空开；多个触发 DOT 独立记录连线加成；飞行敌人也能响应适用效果 |
| S2 连星 | 连线方向两侧三格伤害、减速与主动补子 | 横／纵激活方向在相邻子消失后仍按规则保留；多个减速独立计时 |
| S3 天下劫 | 扩触发范围；停止普攻；棋子补给、自动跟子、手动投放例外与二十发弹药 | 手动投放能落敌人格；额外跟子扣弹药；停止／耗尽按原规则结束，剩余弹药返还库存 |
| 棋子与跟子 | `token_10064_wang_stone1` 及技能依赖，跟子单独保存来源与生成代次；S1 的施加者与无来源结算单独处理 | S2／S3 棋子与跟子的来源不同，S1 不套这条通则；主人退场清理；新部署覆盖跟子时跟子消失 |
| X 模组 | 部署费用、同时部署上限、连线强化与属性 | 与基础库存上限分开；五／六阶不混用模组天赋 |

不能用“一个圆形陷阱圈”替代方向连线，也不能给跟子添加干员部署占用。备战、开战、跨回合和存档需明确哪些是布局、哪些是消耗品状态；不得让所有棋子沿用现有战斗型召唤卡的自动复现队列。自动作战若提供辅助投放，须另列为项目策略并保持确定性，不能替代手动投放的基础机制验收。

开放前核定两项来源差异：PRTS S3 备注的 `x-1` 与原表 token `x-6` 几何不同；棋子页仅说明精一后再部署 3 秒，本地精二为 2 秒。两项不能因数值包完整而自动视为通过。

### 克莱门莎

实体 `char_4231_clemnt`，分支 `primguard`。固定版本数据是前置工作。现有侵蚀累计、敌方侵蚀爆发结算和 `element-burst` 事件可复用；基准防御、放逐和轰炸仍需专属处理。依据 [PRTS 克莱门莎](https://prts.wiki/index.php?oldid=440582)。

| 能力 | 实施内容 | 定向验收 |
| --- | --- | --- |
| 生死定夺 | 每段物理伤害按目标实时防御与出生基准比较，选择暴击概率 | 保留不可变的出生基准；初始防御为零不误入强化概率；多段独立判定 |
| 习得性防御 | 根据来源格位、朝向、被阻挡关系和海怪分类减免 | 前方、侧线、后方及被阻挡目标分别测；仅对适用物理／法术伤害生效 |
| S1 冲蚀 | 下一次攻击倍率与实际已造成伤害对应的侵蚀累计 | 零伤害不累计；弱点转换等适用路径仍以最终结算结果计量 |
| S2 风暴潮 | 强制缴械、放逐组合、放逐舱运输、停止后的漩涡和技能攻击；主目标与 100% 攻击力溅射分开 | 无敌／不可阻挡／无法行动随放逐生效；重量额度和人数独立计数；障碍提前停；漩涡按每秒结算 |
| S3 与海为敌 | 技能普攻附加侵蚀；全场侵蚀爆发触发标记、弹道轰炸与十发弹药 | 消耗来自成功发射轰炸，不是普通攻击；同格不重复开火；持续轰炸的物理与元素伤害分别记账 |
| 模组 | 固定包中有适用模组才加载 | 不以六阶为理由虚构模组和强化能力 |

现有 `settleElementBurst` 会降低目标 `baseDef`，因此第一天赋必须另外保存不随侵蚀降低的出生防御基准。不要将当前可变 `baseDef` 误当原始值。放逐是受免疫、可达性和承载重量限制的跟随传送，不等同于原生推拉；负重量、静态刚体、自缚、飞行和传送免疫分别核对。

S2 的放逐舱按地面运输处理，漩涡对空单独处理；S3 监听其它来源造成的全场侵蚀爆发，不能只看自己打出的爆发。轰炸以目标格和周围四格判定，不能改成圆形范围。每个附属弹道、标记、重量余额、命中与计时都进入逻辑快照，显示事件仅用来绘制。

## 公共规则和交互验收

| 场景 | 必须证明的结果 |
| --- | --- |
| 空配置、一个人、两个人 | 原池保持可用；人数不影响默认预设库存；只有已选阶级入池 |
| 改人物或改阶级 | 新开局采用新配置；正在玩的本局和恢复存档继续旧配置 |
| 商店等级与库存 | 普通商店刷新须达到所选阶级；晋升等特殊奖励仍遵守已有可超一级的规则；抽取继续先掷阶级再按库存取人 |
| 买三份与出售 | 三合一得到相应阶级精锐；装备和位置沿用现有合成规则，购买记录正确回补 |
| 晋升、策略、装备和盟约奖励 | 选中人物在适用范围可获得；未选人物、另一阶和被禁身份无法漏入 |
| 阵营与禁用 | 炎／阿戈尔／协防人数、成员效果、禁用预览和实际获取一致；精锐不绕过禁用 |
| 没有自带卫戍 | 获得、刷新、出售、回合结算均不触发借来的其它人物自带特质；合法外部转发效果仍能工作 |
| 存档输入 | 旧存档缺少选择按空配置恢复；非法选择、与配置矛盾的棋子、库存和 offers 拒绝恢复 |
| 多个本局数据视图 | A 局选人不会改 B 局或大厅基础数据，名册缓存没有旧绑定 |
| 基础联动 | 弱点伤害、S.E.E.S. 核心、炎范围加成、阿戈尔效果、协防伤害与装备分别验证 |
| 地图和最终 Boss | 高台、围栏、深水、沙尘暴、沼泽、气流、传送与 Boss 占区不被新投放／特殊移动绕开 |
| 暂停与恢复 | 分段技能、随机序列、弹药、DOT、召唤物、弹道和标记恢复后的下一事件与未中断运行一致 |
| 统计 | token、余震、爆炸、持续伤害与轰炸归属正确，不抬高干员普通攻击次数或敌方非衍生击杀数 |

“资料已采集”“处理器已注册”“实际场景通过”保持独立。自选状态单独登记，不把原有 112 名预设范围或全局 `acceptedScopeComplete` 自动改成完成。

## 实施前需保留的决策记录

目前没有阻止实施方案成立的待答问题。后续开工按本页默认值推进；以下若用户另有偏好再调整：是否允许同人跨阶重复、是否开放阿斯卡纶 Y 模组、每周挑战是否锁定自选阵容、望是否增加自动投放策略。它们不应拖延基础系统与已确定逐名机制的开发。
