# 敌人重叠显示

2026-10-09：采用上方血条堆栈方案，入口为 `dist/native-enemy-overlap.js`，由 `native-play.draw()` 接入。

- 只读投影坐标判断重叠；同组头像作小幅错开交叠，不改写敌人坐标、路线、阻挡和受击数据。
- 同组按敌人 uid（出生顺序）固定排序，血量变化不重排。合并距离小于分离距离，避免边缘闪烁；按锚点约束分组，避免一串敌人把整条路线合并。
- 2–4名显示逐名小头像和独立血条；更多敌人保留四行，按钮显示总数及隐藏行数。次数生命显示剩余次数，不合成平均血量。
- 点击行高亮对应头像，点击计数按钮展开完整名单（名称、生命/次数、主要状态）；名单随存活成员更新。再次点击计数、关闭或Esc收起，键盘焦点返回对应计数按钮。手机以44px计数入口打开，再在完整名单选择。
- 堆栈优先放在上方，碰到其它堆栈时尝试左右侧，约束在棋盘范围内；详情放在离目标较远的一侧，避免盖住选中头像。极密集场景下可用空间仍受棋盘尺寸限制。
- 死亡、隐藏、最终Boss与测试木桩不混入常规计数，Boss维持独立血条。隐匿成员的小头像维持压暗。血条和状态最多每150ms刷新，移动位置逐帧更新。
- 展开和选中状态属于界面，不入战斗存档。回大厅、备战与切换对局清理。

验证：`node --test tests/native-enemy-overlap.test.mjs`；浏览器 `node scripts/regression-browser.mjs enemy-overlap`，覆盖1/3/4/8/12名、独立血量、次数怪、展开/选择/关闭、回大厅清理、手机横屏尺寸与触控。
