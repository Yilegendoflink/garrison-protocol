# 编制台活动分组

2026-09-21：本期 215 条敌人档案使用 PRTS 的「登场活动」属性分组，来源快照为 `data/prts/enemy-activities.json`，逐条保留页面链接。同名干员使用「(敌方)」页面；上下位和同名不同 ID 的敌人仍各自保留记录。活动是登场归属，不代表只会在该活动出现。

- 编制台默认显示本地 `randomPoolEligible` 已准入的敌人，目前 177 条；可按活动、逻辑状态、词条、移动与来源组合筛选。已准入不代表所有原作时序、场景或表现已验收，范围继续遵守敌人行为审计。
- 模板按同一登场活动约束；第一名敌人确定活动，空模板也可主动选择活动。池非空时需先移出敌人再改活动。批量填入只取同活动、已准入、符合当前词条及成本上限的敌人。
- 默认配置按原模板的活动拆分，同档同活动合并去重，并剔除未准入敌人；原有敌人成本、预算、数量范围和早期成本上限保留。允许单敌人模板，不通过混入别的活动凑种类。
- 旧存档/导入表保留预算、费用与数量配置，载入时拆分混合模板。随机抽取也再次按活动拆分并过滤未准入敌人；有非空池时不抽取空池，全部为空才沿用占位敌人。实战按整档随机选模板。编制台的「测试当前模板」只把当前选中的一套交给同一预算/资格规则，主动点击后以弹窗显示；当前模板为空时显示占位结果，不能回退到其他模板。
- 旧自定义表中的待补齐敌人仍可见、可移出，不能新加入，也不会被随机抽出。保存后的表仍使用兼容的 v2 存储键。

更新资料：`node scripts/sync-enemy-activities.mjs`；随后 `npm run build`。构建会校验每条活动归属、默认模板同活动与逻辑资格；新敌人或活动变化须逐条复核默认 JSON，不能靠分类放开机制资格。

界面采用模板侧栏、当前模板设置、敌人池和档案分区；配置管理与高级筛选默认收起，属性与独立难度编辑在点选档案后显示。抽取结果按同名敌人汇总，支持再抽一次、关闭按钮、Esc 和遮罩关闭。

验证：`node --test tests/native-wave-*.test.mjs`；浏览器：`node scripts/regression-browser.mjs wave-activities`。
