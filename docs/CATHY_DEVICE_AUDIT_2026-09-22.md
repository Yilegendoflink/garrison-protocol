# 凯瑟琳「支援装置」（爬行号·防护单元）审计（2026-09-22）

起因：用户报「凯瑟琳的召唤物依然不能正确放置在场上，查看 prts wiki 信息补全缺口」。
结论：**落点规则被统一套成了战术家的「只能在攻击范围内选点」**，装置实际只能放在她自己脚下或身前那一格；
同时屏障的目标与数值有若干写死／漏项。本页记录 PRTS 依据、修改点、实测数据与仍未闭环的部分。

## 一、PRTS 依据（本地快照 `data/prts/snapshots/2026-09-12-prts/`）

**干员页 · 凯瑟琳**（`source/72129.json`，prts:operator:72129，revisionId 394093）

- 职业 辅助／分支 **工匠**／位置 近战位；特性「能够阻挡两个敌人，使用**〈支援装置〉**协助作战」。
- 分支信息（决定装置归属）：
  - 可以且优先攻击自身阻挡的单位（即使目标处于攻击范围外或为飞行单位）；
  - **干员部署后，按天赋描述数量补充支援装置持有数**；
  - **干员离场后，附属的支援装置随之消失**。
- 天赋 定向支援信号：携带 2 个（精英0）／3 个（精英1 起）支援装置（**最多部署 2 个**），使一名干员获得
  相当于凯瑟琳生命上限 10%／15%／20% 的屏障（潜能5 +2%），若目标最近 5 秒内未受攻击则每秒补充
  相当于生命上限 6% 的屏障、不超过初始上限，**装置效果不叠加**。
- 模组 CRA-X「闲暇时分」：〈支援装置〉持有上限 **+1**、部署费用 **-2**（对应精锐形态的 `cnt: 4` 与 `cost: 3`）。

**召唤物页 · 爬行号·防护单元**（`source/72127.json`，prts:summon:72127，oldid 386131）

| 字段 | 值 |
| --- | --- |
| 部署位置 | **全部位**（近战位／远程位都能落） |
| 部署费用／再部署 | 5（模组 -2 → 3）／15 秒 |
| 阻挡数／部署占用数／嘲讽等级 | 0／**0**／0 |
| 特性 | 不会受到攻击 |
| 召唤物天赋 | 定向支援信号：**使攻击范围内**一名友方干员获得屏障（分档 10–22%） |

token 自带天赋黑板（`token_10041_cathy_catsld.talents[0]`，随持有者精英阶段解析）：
`cnt`(2/3)、`max_shield_ratio`(0.1/0.15/0.2)、`shield_ratio_each_trigger`(0.06)、`interval`(5 秒静默窗口)、
`catsld_t_1[timer][interval].interval`(1 秒结算间隔)。**这些就是屏障数值的唯一来源**，不要写死。

**对照 · 战术家**（`data/prts/branch-rules.json`）：特性「可以在**攻击范围内**选择一次战术点来召唤援军」——
狼群／流形受攻击范围限制是对的，问题在于这条口径被一起套到了工匠的装置上。

旁证（第三方，非权威）：「部署时需对准友方干员触发／每位干员仅能获得一个装置的增益效果／
先布置装置、后部署的干员依旧能获得护盾增益／凯瑟琳被击败或撤离时场上装置一同消失」。

## 二、修改点（`dist/native-session.js`／`native-effects.js`／`native-battle.js`）

1. **落点**：`summonCardRange` 增设 `SUMMON_FREE_PLACEMENT`（当前只有 `cathy-device`）——工匠装置按
   「部署位置：全部位」与普通单位一样按格子选，**不受凯瑟琳攻击范围限制**；同一格也可以（部署占用数 0）。
2. **携带数量**：`summonCardSpecs` 取干员天赋黑板的 `cnt`（初始 3／精锐带模组 4），不再写死 3；
   同时部署上限取 token 的 `maxDeployCount`（2），与「最多部署 2 个」一致。
3. **干员压在装置上**：`canDeploy` 对部署占用数 0 的装置不再拦人，
   「先把装置摆好、干员后上场」成立。
4. **屏障目标**：新增 `native-effects.tickCathyDevices`——每秒按**装置自己的攻击范围**
   （token `rangeId` = `1-1`＝自身格＋身前格，朝向取放置时选的朝向）复查一名友方干员；
   凯瑟琳本人也可以是目标（对准她自己就是自辅自护）；换目标时把旧目标身上那份撤掉。
   `native-battle.spawnPreparedSummons` 开战即调用一次，所以装置落地立刻发屏障。
   顺带修好 `spawnSummon` 时装置朝向只有 `card.dir` 才生效（`native-battle` 里补传 `dir`）。
5. **装置效果不叠加**：屏障 id 按「持有者＋目标」复用（`cathy-shield-<owner>-<target>`），
   两个装置盖同一名干员时只有一份屏障，每秒也只结算一次。
6. **数值取黑板**：`capRatio`／`eachRatio`／`interval`／`quiet` 全部来自 token 天赋（不再写死 .2／.06／5）。
7. **一技能「岁月锻打」**：PRTS 是「**自身**和拥有装置屏障的其他干员」，所以 `自身` 改为无条件吃攻防加成
   （此前只有成为装置目标时才吃）。

## 三、实测（同一场景，改前 → 改后）

地图 seed=1（19 个可部署格），凯瑟琳在 (3,0)、崖心在 (4,0)：

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 装置卡可放置格 | **2 格**（⌊3,0⌋ 自己脚下、⌊4,0⌋ 身前） | **19 格**（全部可部署格） |
| 屏障目标 | 生成时取「离卡最近的单位」，**不看范围**且排除凯瑟琳 | 每秒按装置自身攻击范围（1-1）复查，凯瑟琳也算 |
| 屏障数值 | 写死 20%／6%／静默 5 秒 | token 天赋黑板（随精英阶段 10/15/20%） |
| 不叠加 | 每个装置各一层（同一人可叠两份） | 同一人只有一份，每秒只结算一次 |
| 携带数量 | 写死 3 | 初始 3／精锐带模组 4（`cnt`） |
| 干员压在装置格 | 不允许 | 允许（部署占用数 0） |
| 开局屏障 | 428.8（= 2144 × 20%），目标常是「最近的单位」 | 428.8，目标是装置范围内的人 |
| 打掉到 100 后：4.9s／6.1s／20s | — | 100（静默窗口内不补）／357.3（5.0s、6.0s 各补 6%）／428.8（封顶） |
| 二技能期间 3.1s | — | 395.9（10 + 3×128.6，每秒无条件补 6%） |

## 四、回归

`tests/native-cathy-device.test.mjs`（7 条）：落点放开（含「战术家仍受限」的反向门禁）、
装置按自身范围选目标、部署占用数 0 的同格流程、装置效果不叠加、
5 秒静默窗口与二技能每秒补充的数值、换目标撤掉旧屏障＋一技能自身加成、数值取黑板＋离场装置消失。

## 五、待办（本次未改）

1. **二技能「停止攻击」没有实现**：`native-operator-effects.operatorSkillConfig` 已经解析出
   `stopAttack`（文案「停止攻击／无法普通攻击」），但**全项目没有消费者**（`native-battle` 不读它），
   所以凯瑟琳 S2 期间仍会普通攻击（地灵 S2 等同类技能也一样）。要做得先定口径
   （是否连技能期间的额外攻击一起停），再在 `native-battle` 的攻击决策处消费。
2. **模组的天赋强化没有数据**：PRTS 写 CRA-X 2/3 级把屏障提升到 25%／28%，但本期数据包的
   `modulePhase` 只有 `cost:-2` 与 `max_deck_stack_cnt:+1`，没有 `max_shield_ratio` 的覆盖，
   所以精锐形态按 token 天赋的精英2档 20% 结算。
3. **瞄准交互**：真机是「对准友方干员」部署，本客户端没有这套瞄准动画，只按「同格优先 → 距离 → uid」
   在范围内选一个目标。
4. **同格共存的逐帧表现**：允许干员压在装置格上的依据是 PRTS 的「部署占用数 0」＋分支信息的
   「附属的支援装置」，没有与原作逐帧对照。
